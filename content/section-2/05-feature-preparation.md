Алгоритм машинного обучения принимает на вход числовую матрицу без пропусков. Клиническая таблица такой не бывает: в ней есть категории, пропуски и показатели в несопоставимых единицах. Этот урок — о том, как превратить одно в другое и не испортить при этом будущую оценку модели.

## Сначала разделить, потом готовить

Чтобы честно оценить модель, часть пациентов откладывают и не показывают ей при обучении. Это разделение делают **до** любой подготовки признаков — причину разберём чуть ниже.

```python
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split

hd = pd.read_csv("heart_disease.csv")
hd[["chol", "trestbps"]] = hd[["chol", "trestbps"]].replace(0, np.nan)
hd["target"] = (hd["num"] > 0).astype(int)

features = ["age", "sex", "cp", "trestbps", "chol", "thalach", "exang", "oldpeak"]
X, y = hd[features], hd["target"]

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
print(X_train.shape, X_test.shape)
print("Доля ИБС:", round(y_train.mean(), 3), round(y_test.mean(), 3))
```

```output
(690, 8) (230, 8)
Доля ИБС: 0.554 0.552
```

Три параметра стоит запомнить: `test_size` — доля отложенных пациентов, `random_state` — фиксирует случайное разбиение, чтобы результат воспроизводился, `stratify=y` — сохраняет одинаковую долю больных в обеих частях.

## Кодирование категорий

Тип боли в груди записан числами от 1 до 4. Если передать этот столбец модели как есть, она решит, что «боли нет» (4) вчетверо «больше» типичной стенокардии (1). Чтобы этого избежать, категорию превращают в несколько бинарных столбцов — по одному на каждое значение. Приём называется **one-hot-кодированием**.

```python
print(pd.get_dummies(X_train["cp"], prefix="cp").astype(int).head(4))
```

```output
     cp_1  cp_2  cp_3  cp_4
387     0     0     0     1
831     0     1     0     0
570     0     0     0     1
630     0     0     0     1
```

В каждой строке ровно одна единица. Порядковые признаки (стадия, функциональный класс) иногда оставляют числом, если шаги между уровнями можно считать примерно равными; номинальные — кодируют всегда. Бинарные признаки в кодировании не нуждаются.

## Масштабирование

```python
print(X_train[["age", "chol", "oldpeak"]].agg(["mean", "std"]).round(2))
```

```output
        age    chol  oldpeak
mean  53.57  247.27     0.89
std    9.49   60.70     1.11
```

Холестерин измеряется сотнями, депрессия ST — единицами. Для методов, которые опираются на расстояния между пациентами или штрафуют большие коэффициенты (метод ближайших соседей, регуляризованная логистическая регрессия), это проблема: признак с большими числами начинает доминировать просто из-за единиц измерения.

**Стандартизация** приводит все количественные признаки к одной шкале: из каждого значения вычитают среднее и делят на стандартное отклонение. После неё у признака среднее 0 и разброс 1, а значение показывает, на сколько стандартных отклонений пациент отличается от среднего.

Деревьям решений и построенным на них ансамблям масштаб безразличен: они сравнивают значения с порогом, а не между собой. Сильно скошенные признаки (креатинин, КФК) перед стандартизацией часто логарифмируют.

## Заполнение пропусков

В выбранных признаках есть пропуски: холестерин, давление, показатели нагрузочной пробы. Самый простой способ — заменить пропуск медианой (для количественных) или самым частым значением (для категорий).

У простого заполнения есть цена: оно занижает разброс признака и ослабляет его связи с другими. Если сам факт пропуска может быть информативен — а в медицине это частый случай, — добавляют отдельный столбец-индикатор «значение отсутствовало».

## Главное правило: учиться только на обучающей части

Медиана для заполнения, среднее и стандартное отклонение для масштабирования, список категорий — всё это **параметры, которые оцениваются по данным**. Если посчитать их по всей таблице, информация о тестовых пациентах просочится в обучение, и оценка качества окажется завышенной. Это называют **утечкой данных**.

Правило простое: `fit` — только на обучающей выборке, `transform` — на обеих. Чтобы не ошибиться, все шаги собирают в один объект.

```python
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

numeric = ["age", "trestbps", "chol", "thalach", "oldpeak"]
categorical = ["cp"]
binary = ["sex", "exang"]

preprocess = ColumnTransformer([
    ("num", Pipeline([
        ("imputer", SimpleImputer(strategy="median")),
        ("scaler", StandardScaler()),
    ]), numeric),
    ("cat", Pipeline([
        ("imputer", SimpleImputer(strategy="most_frequent")),
        ("onehot", OneHotEncoder(handle_unknown="ignore", sparse_output=False)),
    ]), categorical),
    ("bin", SimpleImputer(strategy="most_frequent"), binary),
])

X_train_prepared = preprocess.fit_transform(X_train)
X_test_prepared = preprocess.transform(X_test)
print(X_train_prepared.shape, X_test_prepared.shape)
print(list(preprocess.get_feature_names_out()))
```

```output
(690, 11) (230, 11)
['num__age', 'num__trestbps', 'num__chol', 'num__thalach', 'num__oldpeak', 'cat__cp_1', 'cat__cp_2', 'cat__cp_3', 'cat__cp_4', 'bin__sex', 'bin__exang']
```

`ColumnTransformer` применяет к каждой группе столбцов свою цепочку шагов и склеивает результат. Восемь исходных признаков превратились в одиннадцать: пять количественных, четыре столбца для типа боли и два бинарных. Параметр `handle_unknown="ignore"` страхует от ситуации, когда в новых данных встретится категория, которой не было при обучении.

Убедимся, что параметры действительно взяты из обучающей части.

```python
imputer = preprocess.named_transformers_["num"].named_steps["imputer"]
print("Медианы для заполнения:", dict(zip(numeric, imputer.statistics_.tolist())))
print("Средний возраст после масштабирования:")
print(f"  обучающая: {abs(X_train_prepared[:, 0].mean()):.3f}")
print(f"  тестовая:  {X_test_prepared[:, 0].mean():.3f}")
print("Пропусков осталось:", int(np.isnan(X_train_prepared).sum() + np.isnan(X_test_prepared).sum()))
```

```output
Медианы для заполнения: {'age': 54.0, 'trestbps': 130.0, 'chol': 239.0, 'thalach': 140.0, 'oldpeak': 0.5}
Средний возраст после масштабирования:
  обучающая: 0.000
  тестовая:  -0.024
Пропусков осталось: 0
```

В обучающей части средний возраст после масштабирования равен нулю — именно по ней считались параметры. В тестовой он немного отличается от нуля, и это правильно: тестовых пациентов преобразовали «чужими» параметрами, как это произойдёт с любым новым пациентом в клинике.

::: clinic Аналогия с референсными значениями
Референсный интервал лабораторного показателя устанавливают заранее на выборке здоровых людей и затем применяют к каждому новому пациенту. Никто не пересчитывает норму, добавив в выборку самого обследуемого. Подготовка признаков устроена так же: параметры определяются один раз на обучающих данных и дальше только применяются.
:::

## Отбор признаков

Не каждый столбец стоит включать в модель.

- **Почти пустые признаки.** `ca` и `thal` заполнены в основном в одной клинике; модель, которая на них опирается, бесполезна там, где эти исследования не делают.
- **Признаки, недоступные в момент прогноза.** Если модель должна помогать при первичном осмотре, в ней не может быть результата ангиографии.
- **Дублирующие признаки** — коллинеарные пары из прошлого урока.
- **Идентификаторы и технические поля**: номер истории болезни, дата выгрузки.

::: warning Отбор признаков — тоже обучение
Если выбрать «десять признаков, сильнее всего связанных с исходом» по всей таблице, а потом оценивать модель на отложенной части, оценка будет завышена: тестовые пациенты уже повлияли на выбор. Отбор по данным делают только на обучающей выборке — внутри того же конвейера.
:::

::: summary
- Данные делят на обучающую и тестовую части до любой подготовки; `stratify` сохраняет долю больных.
- Номинальные категории кодируют one-hot, количественные признаки стандартизируют, пропуски заполняют медианой или частым значением.
- Все параметры подготовки оцениваются только по обучающей выборке (`fit`), к тестовой их лишь применяют (`transform`).
- `Pipeline` и `ColumnTransformer` собирают шаги в один объект и защищают от утечки данных.
- В модель включают признаки, которые доступны в момент прогноза и заполнены у большинства пациентов.
:::
